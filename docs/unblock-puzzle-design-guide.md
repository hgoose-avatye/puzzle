# 막힌 조각 빼내기 퍼즐 디자인 지침

Unblock / Slime / Screw / Unjam 스타일 퍼즐의 디자인 원칙이다. 구현할 때 참고하기 위해 남긴다.

- 1~4절은 사용자가 제공한 지침을 그대로 옮긴 것이다(오타만 수정).
- 5절은 이 지침을 앞서 한 분석 결과와 연결한 것으로, **분석자가 추가한 내용**이다. 사용자가 확정한 사항이 아니다.
- 관련 문서: [Arrows 분석](arrows-game-analysis.md), [Parking Jam 3D 분석](parking-jam-3d-analysis.md)

---

막힌 조각을 순서대로 빼내는 퍼즐 게임 디자인은 **'답답함(Constraint)과 해소감(Catharsis)의 낙차'** 를 설계하는 것이 핵심이다. 현재 유행하는 모바일 퍼즐(너트와 볼트 조이기, 블록 밀어내기, 탈출 퍼즐 등)의 성공 공식을 바탕으로 기획 방향을 정리한다.

## 1. 코어 메카닉과 공간 제약 설계 (Puzzle Architecture)

- **간섭(Interference)의 시각화**
  - 조각들이 서로 물리적으로 얽혀 있거나, 진행 방향(Vector)이 가로막혀 있어야 한다.
  - "이 조각을 빼려면 저 조각을 먼저 치워야 한다"는 인과관계를 플레이어가 화면을 보자마자 직관적으로 파악할 수 있어야 한다.
- **이동 경로와 순서의 층위(Layers)**
  - 단순히 한 방향으로 미는 것을 넘어, 겹쳐 있는 레이어(상/하, 앞/뒤) 개념을 도입한다.
  - "어느 구멍으로, 어떤 순서의 회전이나 이동을 거쳐야 빠지는가"를 고민하게 만든다.
- **공간의 한계(Bottleneck)**
  - 이동할 수 있는 빈칸이나 슬롯의 개수를 제한한다.
  - 플레이어가 무작위로 시도(Trial and Error)하는 것을 막고 한 수 앞을 내다보도록 유도한다.

## 2. 난이도 곡선과 스테이지 프로그레시브 (Difficulty Curve)

### 학습 단계 (Tutorial & Introduction)

- 조각이 3~4개 이하인 상태에서 '밀어내면 바로 해결되는 쾌감'을 먼저 학습시킨다.
- 막힌 조각이 다른 조각을 밀어내는 상호작용(연쇄 반응)을 자연스럽게 인지시킨다.

### 응용 및 복잡도 증가 (Mid-game)

- 조각의 형태를 다양화한다(ㄱ자, 십자가, 긴 바 형태 등).
- 특정 조각은 특정 방향으로만 움직일 수 있는 제약 조건(Lock)을 추가한다.
- '가장 먼저 빼야 할 키오브젝트(Key Object)'를 숨겨두어 역순으로 추론하는 재미를 준다.

### 심화 단계 (End-game)

- 제한된 이동 횟수(Move Limit)나 타임어택 요소를 가미해 긴장감을 높인다.
- 겉보기에는 절대 빠지지 않을 것처럼 얽혀 있다가, 마지막 한 조각을 빼는 순간 도미노처럼 주르륵 빠져나가는 **'대형 해소감(Satisfying unjam)'** 배치를 설계한다.

## 3. 플레이어 심리와 피드백 디자인 (UX & Juice)

### 시각적·청각적 피드백 (Game Juice)

- 조각이 꽉 낀 상태에서 뺄 수 없는 방향으로 밀려고 할 때의 묵직한 덜컥거림(Haptic & Sound)과, 쏙 빠질 때의 **청량한 타격음·슬라이드 효과음**이 퍼즐 게임의 리텐션을 좌우한다.

### 막혔을 때의 완충 장치 (Anti-frustration)

- 중장년층이나 라이트 유저도 즐길 수 있도록, 너무 막힐 때는 힌트 시스템이나 '특정 조각을 일시적으로 치워주는 도구'를 제공하여 이탈을 방지한다.
- 실패했을 때 처벌을 주기보다는 "한 번 더 시도하면 될 것 같은" 오기를 자극하는 판 벌림이 중요하다.

## 4. 격자 규격, 역설계 기법, UX 보완 (추가 지침)

### 4.1 격자 규격(Grid Size)과 블록 형태의 다양화

**격자 크기 설정**

- **3x3 / 4x4:** 가볍게 즐기는 초급 단계. 경우의 수가 적어 직관적인 시행착오로 풀 수 있다.
- **5x5 / 6x6 (표준):** 가장 대중적이고 전략적 깊이를 주기 좋은 크기다. 공간의 여유(빈칸)가 1~2개뿐일 때 가장 높은 몰입감을 준다.

**블록의 성격(Dimension) 분화**

- **정사각형 블록 (1x1, 2x2):** 공간을 차지하는 덩어리로, 다른 블록의 이동 통로를 막는 거대한 장애물 역할을 한다.
- **직사각형 바(Bar) 형태 (1x2, 1x3, 2x1 등):** '가로 방향으로만' 또는 '세로 방향으로만' 움직일 수 있는 **축의 제약(Axis Constraint)** 을 부여한다. 이 제약이 생기는 순간 퍼즐의 난이도가 확 올라간다.

### 4.2 '막힘과 해소'의 인과관계 디자인 (Reverse Engineering 기법)

좋은 레벨을 만들 때는 완성된 상태(탈출 성공 상태)에서 거꾸로 역추적(Reverse Engineering)하며 설계해야 한다.

1. **탈출구 설정:** 핵심 블록(또는 탈출해야 할 대상)이 빠져나갈 출구를 격자 한쪽 끝에 지정한다.
2. **역순 배치:** 출구를 막고 있는 블록을 한 칸씩 뒤로 밀어내며 장애물들을 배치한다.
3. **간섭 유도:** "이 블록을 빼려면 저 긴 바 형태의 블록을 위로 치워야 하고, 그러려면 작은 블록 두 개를 옆으로 비켜야 하는" 최소 3~4단계의 연쇄적 의존성(Dependency)을 만든다.
4. **최소 이동 횟수(Min Moves) 검증:** 플레이어가 무작위로 밀어보다가 우연히 깨는 것을 막기 위해, 최소 몇 번을 움직여야 깨는지 계산하여 스테이지의 난이도 지표로 삼는다.

### 4.3 막힌 조각의 스트레스를 완화하는 UX 장치

중장년층이나 라이트 유저를 타겟으로 할 때, 너무 막히면 쉽게 이탈하므로 다음과 같은 보완책이 필요하다.

- **한 방향 제한 가이드:** 블록을 터치했을 때, 현재 구조상 "이 방향으로는 막혀서 안 움직인다"는 것을 시각적(흔들림 애니메이션)이나 묵직한 사운드로 즉시 알려준다. "오류가 아니라 내 두뇌의 착각"임을 인지시킨다.
- **스텝백(Undo) 기능:** 2차원 슬라이드는 한 번 잘못 밀면 도리어 판이 꼬여 처음부터 다시 해야 하는 스트레스가 크다. 무제한 혹은 여유로운 '한 수 되돌리기(Undo)' 기능을 제공하면 과감하게 시도해 보는 재미가 살아난다.
- **핵심 경로 하이라이트 (힌트):** 막혔을 때 "지금 치워야 할 키오브젝트 블록"에 은은한 빛이나 화살표 힌트를 주어 시선을 유도한다.

## 5. 분석 결과와의 연결 (분석자 추가, 미확정)

지침의 각 항목이 원작 데이터에서 어떻게 나타나는지, 구현할 때 어떤 값으로 옮길 수 있는지 정리했다.

### 5.1 지침 → 측정 가능한 지표

| 지침 | 생성기에서 조절·측정할 값 | 원작에서 확인된 것 |
|---|---|---|
| 간섭의 시각화 | 조각마다 "나를 막는 조각" 목록(막힘 관계)을 만들고, 그 수를 제한 | Arrows: 화살표당 평균 막힘 3.1~4.4개 |
| 공간의 한계 | 격자 밀도, 빈칸 수 | Arrows: 밀도 0.37(희소)과 0.8~0.98(밀집) 두 부류 |
| 학습 단계(3~4개 이하) | 조각 수, 라운드 수를 아주 작게 | Arrows 최소 레벨 5개(그룹 07), Parking Jam 일반 레벨 초반 차량 약 7.6대 |
| 연쇄 반응 | 라운드 수(한 번에 풀리는 단계 수), 최장 의존 사슬 | Arrows: 라운드 19~47, 사슬 19~33 |
| 형태 다양화 | 조각 길이·꺾임 수 분포, 스타일 태그 | Arrows: 7종 스타일(Basic, Aztec, Country, Spaghetti, Diag, Snake, Loopy), 평균 꺾임 2.2~4.7회 |
| 방향 제약(Lock) | 특수 조각 종류(열쇠·잠금 등) | Parking Jam: 열쇠·잠금, 체력 차량, 언블록 |
| 키 오브젝트 | 의존 그래프에서 "여러 조각이 기다리는 조각"(진입 차수가 큰 노드)을 일부러 숨김 | 미확인(직접 측정하지 않음) |
| 이동 횟수 제한 | 솔버로 구한 최소 이동 횟수 + 여유값 | Parking Jam: 일반 레벨 28~35%, 챌린지 100%에 제한 |
| 대형 해소감 | 마지막 한 조각을 빼면 연쇄로 나머지가 대량 제거되는 구조 | 아래 5.2 |
| 축의 제약(4.1) | 조각마다 이동 가능한 축(가로/세로)을 데이터에 명시 | Parking Jam: 긴 축 이동 가설이 일반 레벨의 85%를 설명(방향 규칙은 미확정) |
| 최소 이동 횟수(4.2) | 솔버가 구한 최소 이동 횟수를 레벨 데이터에 저장 | Parking Jam: 이동 제한 값이 이와 관련될 가능성(미확인) |
| 한 수 되돌리기(4.3) | 제거·이동 기록을 스택으로 보관 | 미확인 |
| 막혔을 때 완충 | 힌트(풀 수 있는 조각 표시), 일시 제거 도구 | Arrows: 힌트·부스터 클래스 존재, Parking Jam: 목숨·부스터 |

### 5.2 "대형 해소감" 구조를 생성기에서 만들려면

- 막힘 관계가 **비순환**이면 풀이 가능성은 보장된다(Arrows 분석 3절).
- 해소감은 **후반에 제거 가능한 조각이 한꺼번에 늘어나는 곡선**이다. 라운드별 "그 라운드에 빠지는 조각 수"를 보면 알 수 있다.
  - 이상적인 모양: 초반 라운드는 1~3개씩 느리게, 후반 몇 라운드에서 급증.
  - 지금까지는 이 곡선을 원작에서 직접 측정하지 않았다. 구현 전에 측정하면 좋다.
- 생성 후 걸러내기 단계의 **채택 조건 후보**: "라운드별 제거 수의 마지막 구간 증가율이 임계값 이상".

### 5.3 구현 시 우선 확인할 것

1. **난이도 지표와 해소감 지표를 분리**한다. 어렵다는 것과 마지막에 시원하다는 것은 다른 축이다.
2. 학습 단계는 **수작업 레벨 또는 매우 강하게 제한된 생성 규칙**으로 만든다. 생성기에 맡기면 "너무 쉽거나 너무 어렵다"는 문제가 가장 크게 나타나는 구간이다.
3. 힌트는 **솔버를 그대로 재사용**할 수 있다. 지금 나갈 수 있는 조각을 표시하면 된다.
4. 이동 제한은 솔버의 최소 이동 횟수가 필요하므로 **솔버가 먼저**다.
5. 피드백(덜컥거림, 슬라이드음, 이펙트)은 코어와 분리된 **스킨 계층**의 요구사항이다. 코어는 "막힘 시도", "제거 성공" 같은 이벤트만 내보낸다.

### 5.4 4절(추가 지침)과 원작 두 게임의 차이

4절은 블록이 격자 안에서 **밀려 움직이고 판에 남는** 슬라이드형 퍼즐(출구로 핵심 블록 하나를 빼내는 방식)을 기준으로 쓰여 있다. Arrows와 Parking Jam은 조각을 **판 밖으로 빼내 없애는** 방식이다. 두 방식의 차이는 다음과 같다.

| 항목 | 슬라이드형 (4절 기준) | 제거형 (Arrows, Parking Jam) |
|---|---|---|
| 조각이 움직인 뒤 | 판에 남아 다른 조각을 다시 막을 수 있음 | 사라짐. 한 번 빠지면 다시 막지 않음 |
| 풀이 판정 | 상태 공간 탐색 필요(BFS 등) | 그리디 한 번이면 충분(Arrows 확인) |
| 최소 이동 횟수 | 상태 탐색으로 구해야 함 | 제거 횟수 = 조각 수(변주 없음) |
| 난이도 | 이동 횟수가 지표 | 라운드 수, 의존 사슬이 지표 |

- 어느 방식으로 갈지에 따라 **솔버의 복잡도**와 **난이도 지표**가 달라진다. 이 선택은 아직 정해지지 않았다.
- 4.2의 **역순 배치(Reverse Engineering)** 는 두 방식 모두에 맞는다. Arrows 분석에서 제안한 "마지막에 나가는 조각부터 채우는 역방향 생성"과 같은 접근이다.
- 4.3의 **한 방향 제한 가이드(막혔다는 피드백)** 는 Arrows의 `Mistake`, `BlockedAfterMistake`와 연결된다. 원작도 막힌 조각을 탭하면 실패 처리와 피드백을 둔다.

### 5.5 열린 질문

- 방식을 정해야 한다: 슬라이드형(조각이 판에 남음)인가, 제거형(조각이 사라짐)인가. 5.4의 표대로 솔버와 난이도 지표가 달라진다.
- ~~"층위(Layers)" 개념~~ → **평면 격자로 확정**(6.1절).
- ~~조각 모양을 어디까지 허용할지~~ → **A→B→C 단계적 도입으로 결정**(6절).
- 격자 크기. 4.1은 3x3~6x6의 작은 판을 제안하지만, 원작은 Arrows 25~48칸, Parking Jam 일반 레벨 14x12로 훨씬 크다. 6.3절에 제안을 적었다.

## 6. 조각 모양과 타겟: 결정 사항

이 게임에서 가장 핵심이 되는 코어 문제로, 사용자가 지정했다.

### 6.1 확정 (사용자 결정)

- **평면 격자**다. 상/하·앞/뒤 층위(Layers)는 넣지 않는다.
- **타겟은 40~60대 중장년층**이다. 조각 모양, 판 크기, 피드백은 이 타겟의 가독성을 기준으로 정한다.
- **조각 모양은 A → B → C 순서로 단계적으로 도입한다.**

| 단계 | 모양 | 설명 |
|---|---|---|
| A | 직선 막대 | 길이 2~5칸, 4방향. 한 방향으로만 나간다 |
| B | 한 번 꺾이는 ㄱ자 | 직선 + 꺾임 1회 |
| C | 자유 경로 | 여러 번 꺾이는 경로. Arrows 방식에 가장 가깝다 |

### 6.2 분석자 제안 (미확정)

**하나의 데이터 규칙으로 세 단계를 모두 처리한다.**

- Arrows의 규칙(경로 + 머리, 머리 방향 직선 위에 다른 조각이 없으면 나갈 수 있음)에서 A는 꺾임 0회, B는 꺾임 1회, C는 꺾임 여러 회인 특수한 경우다.
- 그래서 코어(조각 데이터, 막힘 판정, 솔버)는 한 번만 만들면 되고, 단계는 **생성기 파라미터**(최대 꺾임 수, 최대 길이)로 조절한다.
- 풀이 판정은 세 단계 모두 그리디 한 번으로 충분하다(Arrows 분석 3절).

**단계별 읽기 부담을 관리하는 장치**

- 단계가 올라갈 때마다 **새 모양을 먼저 쉬운 판에서 소개**한다. 조각 수를 적게 하고 새 모양을 1~2개만 넣는다. 지침 2절의 학습 단계 원칙과 같다.
- 한 판에 **같은 단계의 모양을 섞기 전에**, 이전 단계의 모양이 대부분을 차지하게 하다가 비율을 서서히 바꾼다.
- C 단계에서는 **꺾임 수와 길이에 상한**을 둔다. 원작은 화살표 하나가 평균 2~5번 꺾이고 최대 길이가 40~60칸이다. 이 타겟에게는 훨씬 짧아야 한다(상한값은 시험해서 정한다).
- C 단계에서도 **대각선은 넣지 않는 것을 기본**으로 한다. Arrows의 대각선 레벨은 방향을 눈으로 판단하기 어렵다. 필요하면 가장 마지막 변주로만 둔다.
- 경로를 눈으로 따라가는 부담을 줄이기 위해 **탭하거나 길게 누르면 나가는 길을 보여주는 가이드**를 둔다(Arrows에도 비슷한 가이드라인 기능이 있다).

### 6.3 판 크기 제안 (미확정)

- 원작 Arrows는 25~48칸이라 확대와 스크롤이 필요하다. 이 타겟에게는 부담이다.
- 확대 없이 한 화면에 들어오게 **대략 9×9에서 12×12 이하, 조각 수 약 8~25개**를 출발점으로 제안한다. 숫자는 시험해 보며 조정해야 한다.
- 이 범위는 Parking Jam 일반 레벨(14×12, 차량 약 9대)과 비슷하거나 약간 작다.

### 6.4 방식 확정

- **제거형**(조각이 판 밖으로 나가 사라지는 방식)으로 **확정**했다(사용자 결정).
- 이유: 실수의 대가가 작아 40~60대에게 부담이 적고(판이 꼬이지 않음), 풀이 확인이 가벼워 레벨을 대량 생성하고 걸러내기 쉽다. 슬라이드형(5.4절)과의 비교는 5.4절을 참고한다.
- 단계별 난이도를 어떤 지표로 맞출지는 7절에서 이어서 다룬다.

## 7. 난이도 곡선 기준과 보류 사항

### 7.1 확정 (사용자 결정)

난이도 곡선은 다음 순서로 만든다.

1. **원작 수치를 출발점**으로 삼는다. (Arrows 분석의 라운드 수, 의존 사슬, 밀도 등. [arrows-game-analysis.md](arrows-game-analysis.md) 5, 6절)
2. **40~60대 타겟에 맞춰 낮춰서 직접 설계**한다.
3. **출시 후 플레이 데이터(클리어율, 시도 횟수)로 보정**한다.

### 7.2 분석자 제안 (미확정, 시험으로 정해야 함)

- 원작 Arrows의 라운드 수는 19~47이었다. 이 타겟에서는 **초반 2~5, 후반에도 10~15 정도**로 낮춰 시작하는 안을 제안한다.
- 이 숫자는 근거가 약한 출발점일 뿐이다. 실제로 사람이 해 보며 조정해야 한다.
- 곡선은 한 번에 오르기만 하지 않고, **쉬운 레벨을 중간중간 끼워** 오르내리게 한다(지침 2절의 해소감 원칙). 원작도 같은 난이도 버킷 안에서 레벨을 섞어 순서를 만드는 것으로 보인다(Arrows 분석 6.1절).
- 지표는 5.1절의 **라운드 수, 최장 의존 사슬, 처음부터 나갈 수 있는 비율, 평균 막힘 수**를 쓰고, 해소감 지표(5.2절)는 별도 축으로 둔다.

### 7.3 보류

- **이펙트 방향:** 사용자가 컨셉과 게임 요소를 정한 뒤에 다시 다루기로 했다(보류). 코어와 솔버는 연출과 분리돼 있어 이펙트가 정해지기 전에도 만들 수 있다.
- **게임 컨셉과 에셋 디자인:** 미정.
