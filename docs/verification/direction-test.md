# 방향 맞히기 이용자 테스트 (기존 vs AD)

이용자에게 방향 표시를 설명하지 않고, 동물 10마리가 어느 쪽으로 갈지 맞히게 합니다. 정답률과 응답 시간을 기존 디자인과 AD로 비교합니다.
시안은 [direction-mockups.md](direction-mockups.md)에 있습니다.

## 화면

개발 서버를 같은 Wi-Fi에 열고(`npx vite --config vite.game.config.ts --host`) 폰에서 엽니다.

| 조건 | 주소 |
|---|---|
| 기존 | `http://<PC 주소>:5200/?demo=quiz` |
| AD | `http://<PC 주소>:5200/?demo=quiz&look=AD` |

- 두 조건은 동물 10마리의 위치, 종류, 방향이 같고 동물 모양만 다릅니다.
- 화면에는 번호나 정답이 나오지 않습니다.
- 처음 열 때 규칙 설명 팝업이 뜰 수 있습니다. 진행자가 미리 열어 닫아 둡니다. 팝업에는 "누르면 문 쪽으로 달려간다"는 기본 설명이 들어 있어, 이용자가 읽으면 테스트에 영향을 줍니다.

## 진행

1. 진행자는 "이 동물들이 각각 어느 쪽으로 갈 것 같은지 손가락으로 가리켜 주세요"라고만 말합니다. 눈, 꼬리, 표시 같은 단서는 말하지 않습니다.
2. 아래 순서표의 번호 순서대로 진행자가 동물 하나를 가리키면, 이용자가 방향(위·아래·왼쪽·오른쪽)을 가리킵니다.
3. 응답 시간은 진행자가 동물을 가리킨 순간부터 이용자가 방향을 가리킨 순간까지입니다. 스톱워치로 재거나, 화면과 손을 함께 녹화해 나중에 잽니다.
4. **동물을 누르지 않습니다.** 누르면 실제로 달려가 정답이 드러납니다.

## 같은 사람이 두 조건을 다 볼 때

배치가 같아서, 두 번째 조건에서는 처음 답을 기억해 답할 수 있습니다. 다음 중 하나를 권합니다.

- **사람을 나눠 한 조건만**: 예를 들어 10명 중 5명은 기존만, 5명은 AD만 봅니다. 가장 깨끗합니다.
- **둘 다 보게 할 때**: 절반은 기존을 먼저, 절반은 AD를 먼저 보게 순서를 바꿉니다. 결과는 첫 번째 조건의 답을 중심으로 봅니다.

## 순서표와 정답 (진행자만 봄)

화면 위쪽 왼편부터 대략 읽는 순서입니다. 동물은 종류와 위치로 구분합니다.

| # | 동물 | 칸 수 | 위치(왼쪽부터 x, 위부터 y, 0부터) | 정답 | 비고 |
|---|---|---|---|---|---|
| 1 | 펭귄(어두움) | 1 | (1, 1) | 위 | 등이 카메라 쪽 |
| 2 | 병아리 | 1 | (4, 1) | 왼쪽 | |
| 3 | 뱀 | 3 | (6, 1~3) | 위 | |
| 4 | 허스키(어두움) | 2 | (2~3, 3) | 오른쪽 | |
| 5 | 앵무새 | 1 | (5, 4) | 왼쪽 | |
| 6 | 여우 | 2 | (1, 4~5) | 아래 | |
| 7 | 소 | 2 | (4, 5~6) | 아래 | |
| 8 | 펭귄(어두움) | 1 | (2, 6) | 아래 | 바로 아래에 병아리 |
| 9 | 병아리 | 1 | (2, 7) | 위 | 앞(위)에 펭귄, 카메라 쪽(아래)에 닥스훈트. 붐비는 경우 |
| 10 | 닥스훈트 | 3 | (1~3, 8) | 오른쪽 | |

- 정답 분포는 위 3, 아래 3, 왼쪽 2, 오른쪽 2입니다.
- 정답은 코드의 레벨 정의(`game/demo.ts` `quizLevel`)에서 계산해 확인했습니다.

## 볼 숫자

- 조건별 정답률을 전체, **1칸(#1, 2, 5, 8, 9)**, **2~3칸(#3, 4, 6, 7, 10)**으로 나눠 봅니다. AD는 1칸에서 기존의 바닥 V를 뺐으므로 1칸 정답률을 따로 확인해야 합니다.
- 어두운 동물(#1, 4, 8)과 붐비는 경우(#8, 9)의 정답률을 봅니다.
- 응답 시간의 중앙값을 봅니다(평균은 한 번 오래 망설인 값에 크게 끌림).
- 틀린 답이 "정반대 방향"인지 "옆 방향"인지 봅니다. 앞뒤 혼동이면 정반대로 나옵니다.
