# 터치 인식 문제 분석 (2026-10-30)

실기기 플레이테스트에서 "동물을 눌러도 잘 인식되지 않는다"는 의견이 나왔습니다.
가능한 원인을 하나씩 점검하고, 확인된 원인만 고쳤습니다. 터치 영역(판정 반경 0.75칸)은 넓히지 않았습니다.

## T1 측정

방법:
- 헤드리스 Chrome에서 화면을 4px 간격으로 찍어, 동물 모델이 실제로 그려진 점마다 그 점을 누르면 어떤 동물이 골라지는지 셌습니다.
- 대상은 레벨 1, 10, 34, 60, 90, 120, 150, 180이고, 화면 크기는 360×640, 375×667, 390×844, 412×915입니다.

| | 그 동물이 골라짐 | 다른 동물이 골라짐 | 아무것도 안 골라짐 |
|---|---|---|---|
| 수정 전(바닥 기준) | 65.8% | 15.0% | 19.2% |
| 수정 후(그려진 모델 우선) | **94.2%** | 1.8% | 4.0% |

- 수정 전 "다른 동물"의 96%는 **한 줄 뒤(화면 위쪽) 동물**이었습니다.
- 잘못 골라진 점의 평균 높이는 1.05로, 맞게 골라진 점(0.79)보다 높았습니다. 동물 윗부분을 누를수록 틀렸다는 뜻입니다.
- 카메라가 58°로 내려다보므로 높이 1인 지점을 누르면 바닥 교차점이 약 0.6칸 뒤로 밀립니다.
- 수정 후 남은 빨강·파랑은 대부분 판 가장자리의 **문 표시**입니다. 문은 동물 객체에 속해 그려지지만 누르는 대상이 아닙니다.
- 화면 크기에 따른 차이는 거의 없었습니다(같은 레벨에서 ±1%p).

수정 내용([game/main.ts](../../game/main.ts) `pick`):
1. 손가락 아래로 카메라 광선을 쏴서 처음 맞는 **그려진** 동물의 몸, 색 바닥판, 배지를 고릅니다.
2. 아무 동물에도 맞지 않을 때만 예전처럼 바닥 지점에서 0.75칸 이내의 서 있는 동물을 고릅니다.

`npm run test:e2e`에 회귀 검사를 넣었습니다. 레벨 10에서 그 동물이 골라지는 비율이 90% 이상, 다른 동물은 3% 이하여야 합니다. 현재 결과는 96.0%와 0.5%입니다.

## 추가 확인 (커밋 전)

방법: 헤드리스 Chrome, 수정 후 코드.

**(a) 동물 몸통을 눌렀는데 다른 동물이 골라지는 경우: 없음**
- 레벨 8개 × 화면 크기 2개(360×640, 390×844)에서 확인했습니다.
- 몸·바닥판·배지가 그려진 점 51,851개 중 다른 동물이나 빈 곳이 골라진 점은 0개입니다.
- 남은 오차(위 표의 1.8%, 4.0%)는 모두 문 표시와 방향 표시 같은 "그 밖의 부분"에서 나왔습니다. 이것들은 누르는 대상이 아닙니다.

**(b) 가까이 붙은 동물의 우선순위**
- 손가락 아래 화면에서 **앞에 그려진 동물**이 우선입니다. 카메라에 더 가까워 다른 동물을 가리는 쪽입니다.
- 아무 동물도 그려지지 않은 바닥을 누르면, 예전처럼 0.75칸 이내에서 몸 중심선이 가장 가까운 서 있는 동물을 고릅니다.
- 판 위의 빈 바닥 점 중 이 대체 판정으로 동물이 골라진 비율은 9.6%입니다.

**(c) 움직이는 동물과 서 있는 동물이 겹쳐 보일 때**
- `?demo=cross`에서 이동 속도를 늦추고, 7.5초 동안 달리는 동물이 골라지는 점 9,055개를 조사했습니다. 그중 서 있는 동물이 그 위에 그려진 점은 0개입니다.
- 달리는 동물을 화면에서 12번 눌러도 하트(3)와 다른 동물은 그대로였습니다. 탭 수는 처음 내보낸 1번만 셌습니다.

**(d) 화면 아래 버튼 줄의 가로채기**

| 화면 | 동물이 그려진 점 중 UI에 덮인 점 |
|---|---|
| 세로 320×568, 360×640, 375×667, 390×844, 412×915 (레벨 10·60·120·180) | **0** |
| 가로 667×375, 844×390 | 레벨마다 25~119점. `#bar`(버튼 사이 빈 공간) 13~23점, 버튼(`다시`, `힌트`) 최대 73점, 소리 버튼 1~2점 |

- 가로 화면에서는 판이 아래 버튼 줄까지 내려와 일부 동물을 가립니다.
- 버튼 사이 빈 공간까지 터치를 가로채는 것은 `#bar`가 화면 전체 폭을 차지하기 때문입니다.
- 이 게임은 세로 화면 기준이라 이번에는 고치지 않았습니다.
- 고친다면 두 가지가 필요합니다.
  - `#bar`는 터치를 통과시키고 버튼만 받기
  - 가로 화면에서 판 배치(`Stage.fit`)를 버튼 줄 위로 올리기

## 실기기 진단 화면 (`?touchdebug`, 개발 서버 전용)

폰에서 `http://<PC 주소>:5200/?level=10&touchdebug`처럼 엽니다(서버는 `npx vite --config vite.game.config.ts --host`).

- 손가락이 닿은 곳에 원이 잠깐 남습니다. 초록은 반영됨, 빨강은 거절됨(막힘, 무시, UI가 가로챔), 회색은 그 밖입니다.
- 화면 아래 패널에 최근 9개 입력이 줄마다 나옵니다. 형식은 `↓`(누름) / `↑`(뗌) / `×`(취소), 손가락 번호, 입력 종류(t=터치), 좌표, 골라진 동물, 결과입니다.
- 결과 종류:
  - 누를 때: `pressed`, `pressed a running animal`, `nothing under the finger`
  - 뗄 때: `exited`, `blocked`, `ignored: running`, `ignored: waiting`, `ignored: gone`, `repeat (R1)`, `level over`, `moved off N`(다른 곳에서 뗌), `no press to finish`
  - 취소: `cancelled by the browser`
  - 판에 닿지 못한 터치: `caught by #버튼이름`
- 맨 윗줄에 화면 크기와 devicePixelRatio가 나옵니다.
- 배포 빌드에는 들어가지 않습니다. 동적 import로만 불러오며, 빌드 결과물에서 진단 문구가 0건임을 확인했습니다.

실기기에서 "안 눌린다"는 순간이 오면 패널을 캡처하면 됩니다. 그 줄의 결과가 위 원인 중 무엇인지 바로 보입니다.
