# 2.5D 동물 스프라이트 공통 규격 (최종안, 2026-11-01)

다음 동물부터 이 규격을 씁니다. 게임 규칙·이동 경로·충돌·탈출은 바꾸지 않고, **블록마다 그림만** 바꿉니다.
검증: 1칸 병아리, 2칸 시험 동물, 3칸 악어 (`RESULT.md`). 부품별 그림 사양 예시는 `assets/crocodile/SPEC.md`·`BODY_SPEC.md`·`TAIL_SPEC.md`입니다.

## 1. 부품 구성

| 칸 수 | 부품 (머리부터) | 해당 동물 |
|---|---|---|
| 1칸 | `single` | 펭귄, 병아리, 앵무새 |
| 2칸 | `head`, `tail` | 소, 돼지, 여우, 호랑이, 허스키 |
| 3칸 | `head`, `body`, `tail` | 뱀, 애벌레, 닥스훈트, 악어 |
| 4칸 이상 | `head`, `body` 반복, `tail` | (현재 없음) |

## 2. 방향

블록이 나아가는 쪽 기준입니다. 카메라는 고정이고, 블록만 바닥 위에서 돈다고 봅니다.

| 각도 | 0° | 45° | 90° | 135° | 180° | 225° | 270° | 315° |
|---|---|---|---|---|---|---|---|---|
| 화면 | 아래(카메라 쪽) | 오른쪽 아래 | 오른쪽 | 오른쪽 위 | 위 | 왼쪽 위 | 왼쪽 | 왼쪽 아래 |
| 그림 | 그림 | 그림 | 그림 | 그림 | 그림 | 135° 반전 | 90° 반전 | 45° 반전 |

## 3. 그림 틀

- PNG, **1024×1024**, 투명 배경, 바닥 그림자 없음 (그림자는 게임이 그림)
- **58°** 내려다보는 직교 시점, 좌우 회전 없음 (바닥 칸 선이 화면 수평·수직)
- 칸 1개 = **512px** 폭 (화면 세로로는 434px), 블록이 선 칸의 **바닥 중심 = (512, 640)**
- 블록은 자기 칸 안에 (몸 폭 약 0.92칸). 주둥이·꼬리 끝은 칸 밖으로 0.1~0.15칸까지만
- 조명: 정면 위쪽에서 좌우 대칭 (좌우 반전을 쓰기 위한 조건)
- 밑그림: `assets/crocodile/guide_head_58deg.png`
- 틀이 다른 그림(예: 잘라낸 그림)은 매니페스트에 그림별 기준점을 적어서 씁니다(병아리 방식).

## 4. 파일 이름과 폴더

```
assets/<동물>/
  <동물>.sprites.json            매니페스트
  received-<부품>/               받은 원본 (손대지 않음)
  <부품>-approved/               승인본, 읽기 전용 + SHA256SUMS
    <동물>_<부품>_<각도 3자리>.png   예: crocodile_head_045.png
```

## 5. 매니페스트

```json
{
  "species": "crocodile",
  "frame": { "size": 1024, "cellPx": 512, "anchor": [512, 640] },
  "parts": {
    "head": { "drawn": { "0": "head-approved/crocodile_head_000.png", "45": "…", "90": "…", "135": "…", "180": "…" } },
    "body": { "frontBack": true, "drawn": { "0": "…", "45": "…", "90": "…" } },
    "tail": { "drawn": { "0": "…", "45": "…", "90": "…", "135": "…", "180": "…" } }
  }
}
```

- `drawn`: 실제로 그린 방향만 적습니다. 경로는 매니페스트 기준 상대 경로입니다.
- 그림별 기준점이 다르면 `{ "file": "…", "anchor": [x, y] }`로 적습니다. 이때 `frame.cellPx`는 그 그림에서 칸 1개의 폭입니다.
- `frontBack: true`는 180° 돌려도 같은 모양인 부품(가운데 몸통)에만 씁니다.

## 6. 재사용 규칙

없는 방향은 아래 순서로 채웁니다(`spriteFor` → `nearestSprite`).

1. 그 방향의 그림
2. **좌우 반전:** 반대쪽 방향 그림을 뒤집음. 모든 부품에 허용하되, 조명이 좌우 대칭일 때만
3. **앞뒤 대칭** (`frontBack` 부품만): 180° 돌린 방향의 그림 (그리고 그 반전)
   - 조건: 90° 그림이 좌우 거울상과 같아야 함 (악어 몸통 0.997로 확인)
   - 머리·꼬리·1칸 통짜에는 쓰지 않음 (앞뒤가 다름)
4. **가장 가까운 그림:** 실제 트랙 각도에 가장 가까운 그림. 같은 거리면 시계 방향
   - 반드시 연속 각도로 비교합니다. 8방향으로 먼저 반올림하면 그림이 일찍 바뀝니다(병아리에서 발견한 회귀).

## 7. 그리기 규칙

| 항목 | 규칙 |
|---|---|
| 블록 위치 | 게임 트랙 그대로 (블록 i는 머리에서 i칸 뒤, 모서리 반지름 0.3) |
| 겹침 | 블록마다 머리 쪽으로 **0.10칸** 당겨 그림 (잠정). 규칙·점유 칸·충돌은 그대로 |
| 그리는 순서 | **화면 깊이** (화면 위쪽 블록 먼저). 바위 등 다른 물체와도 한 줄로 정렬 |
| 그림자 | 블록마다 바닥 타원 (게임이 그림) |
| 판 밖으로 나갈 때 | 문을 지나며 0.8칸 안에서 작아지며 사라짐 (기존과 같음) |
| 막혔을 때 | 진행 방향의 옆으로 짧게 흔들림 (기존과 같음) |

## 8. 그림 수량

| 부품 | 최소 | 권장 (꺾일 때 45° 단계) |
|---|---|---|
| 머리·꼬리·1칸 통짜 | 3장 (0°·90°·180°) | 5장 (+45°·135°) |
| 가운데 몸통 | 2장 (0°·90°) | 3장 (+45°) |

| 동물 | 칸 | 최소 | 권장 | 지금 |
|---|---|---|---|---|
| 펭귄 | 1 | 3 | 5 | 0 |
| 병아리 | 1 | 3 | 5 | 3 (잘라낸 그림, 표준 틀 아님) |
| 앵무새 | 1 | 3 | 5 | 0 |
| 소 | 2 | 6 | 10 | 0 |
| 돼지 | 2 | 6 | 10 | 0 |
| 여우 | 2 | 6 | 10 | 0 |
| 호랑이 | 2 | 6 | 10 | 0 |
| 허스키 | 2 | 6 | 10 | 0 |
| 뱀 | 3 | 8 | 13 | 0 |
| 애벌레 | 3 | 8 | 13 | 0 |
| 닥스훈트 | 3 | 8 | 13 | 0 |

| **합계** | | **71** | **117** | 16 |

- **남은 수량:** 최소 55장, 권장 101장
- **최소 수량의 의미:** 대각선 그림이 없어도 게임은 돌아갑니다(병아리 3장으로 확인). 다만 꺾일 때 45° 대신 90° 단위로 그림이 바뀝니다.
- **추가 재사용 후보 (검증 전):**
  - 뱀·애벌레의 몸통은 앞뒤 대칭이면 몸통 2~3장으로 충분합니다.
  - 2칸 동물의 꼬리 쪽 블록이 앞뒤 대칭으로 그려지면 `frontBack`으로 줄일 수 있지만, 꼬리 끝이 있으면 안 됩니다.

## 9. 새 동물 추가 절차 (간소화)

1. **그림 받기:** 칸 수에 맞는 최소 수량을 표준 틀로 받습니다. 첫 장(0°)을 먼저 받아 캐릭터를 확정한 뒤 나머지를 받습니다.
2. **매니페스트 작성:** `assets/<동물>/<동물>.sprites.json` 한 장
3. **프로토타입 등록:** 지금은 `src/main.ts`의 `speciesOf`(칸 수로 고르는 시험용). 실제 게임에서는 레벨의 종 정보로 고릅니다.
4. **자동 검사:** `npx vitest run --config experiments/2-5d-crocodile/vitest.config.ts`
   - 파일 존재, 빠진 방향(`missingHeadings`), 규칙·트랙 일치
5. **눈으로 확인:** 칸 48px 판 위 캡처, 실제 속도 GIF (직선 4방향, 90° 꺾기)
6. **필요하면 보강:** 꺾임이 거칠면 대각선 그림(45°·135°)만 추가
7. **고정:** 승인되면 `<부품>-approved/`에 읽기 전용 + SHA256SUMS

평가는 게임 크기(칸 45~50px)에서만 합니다. 1~2px 차이나 무늬 개수 같은 작은 차이로 멈추지 않습니다.

## 12. 한계

- 종 선택이 칸 수 기준(시험용)이라, 실제 게임에 넣을 때는 종 정보로 바꿔야 합니다.
- 겹침 때문에 몸통·꼬리가 게임 위치보다 블록당 0.1칸 앞에 그려집니다. 그래서 꺾이는 시점도 약 13ms 빠릅니다. 규칙에는 영향이 없습니다.
- 1칸 간격으로 연속 꺾을 때(계단) 블록이 모서리에 모이는 1프레임이 조금 복잡해 보입니다.
- 받은 그림의 바닥 중심은 일부 추정값입니다. 표준 틀로 받으면 이 추정이 필요 없습니다.

## 13. 기록 (2026-11-02, 점유 정합성 진단 후)

- 허용 사항: 악어 90°/270° 머리 그림의 주둥이가 앞 칸으로 약 0.3칸 돌출(몸통 블록은 자기 칸 안). 점유 오인 사례 없음.
- 도구 개선 과제: `tools/import_species.py check`는 표준 기준점 (512, 640)과 `received/` 레이아웃만 가정해, 그림별 anchor를 쓰는
  매니페스트(애벌레 등)와 `approved/` 레이아웃(악어)에서 거짓 실패를 냅니다. 매니페스트의 anchor·경로를 읽도록 고쳐야 합니다(미착수).
- 2.5D 발판: 카드 동물의 색 발판은 검정 10% 반투명 중립 패드로 바뀜(`game/animals.ts`). 게이트·방향 V·fx는 동물 색 유지. Classic 3D는 그대로.
